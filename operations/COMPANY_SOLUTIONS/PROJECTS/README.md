# Projetos e Entregas

Cada trabalho vendido ou formalmente aprovado recebe uma pasta própria:
`PROJECTS/PRJ-YYYY-NNNN-slug/PROJECT.md`

Um projeto pode ser pontual ou vinculado a um contrato recorrente. Não confundir projeto de demonstração interno com projeto contratado.

## Estados do projeto
DISCOVERY, DEMO_ONLY, PROPOSED, APPROVED, IN_PROGRESS, QA, CLIENT_REVIEW, ACCEPTED, DELIVERED, SUPPORT, PAUSED, CANCELLED, CLOSED.

## Regra de criação
- Protótipos internos ficam identificados como DEMO_ONLY e usam dados fictícios.
- Projeto contratado só passa a APPROVED após aceite documentado, escopo, preço, prazo e responsabilidades acordados.
- Integrações, publicação, tratamento de dados reais e acesso a sistemas do cliente exigem autorização explícita e revisão apropriada.
- Criar subpastas conforme necessário: `specs/`, `design/`, `src/`, `tests/`, `delivery/`, `handoff/`. Não colocar secrets ou dados reais sensíveis no GitHub.

Copiar [PROJECT_TEMPLATE.md](PROJECT_TEMPLATE.md). Um projeto por escopo/entrega; mudanças substanciais podem gerar aditivo ou novo projeto vinculado.
